# Fase E.5 — conservación de documentos y candidaturas solo core

## Decisión del propietario

Confirmada el 2026-09-08: **borrar una candidatura conserva CV y carta hasta
borrado explícito o vencimiento de retención**. Portfolio mantiene su plazo
existente de 180 días. La candidatura deja de ser el padre de borrado del
documento; el propietario local sigue siendo obligatorio. No se cambia la
política de borrado de usuarios ni se declara resuelto el tratamiento de backups.

Esta decisión sustituye la pregunta pendiente de E.4; aquella acta se conserva
como fotografía histórica, no como bloqueo vigente.

## Implementación local

- Portfolio consulta la autoridad de candidaturas que usa el Kanban; no crea
  una candidatura local para satisfacer una FK cuando la candidatura solo vive
  en core. La generación sigue escribiendo documentos LOCALMENTE en E.5.
- `application_id` es referencia opaca. `application_snapshot` conserva origen,
  título, empresa, descripción y URL usados para generar, independientemente de
  que después cambie o se borre la candidatura.
- Ambos LLM siguen fuera de transacción. Antes de guardar se revalida la
  candidatura en su autoridad; en local se mantiene el lock corto. Si desaparece
  durante el LLM antes de esa comprobación, devuelve 404 y no guarda. Tras guardar,
  borrar la candidatura ya no elimina los documentos.
- Lectura, PDF y borrado explícito siguen acotados al dueño del documento, sin
  depender de que exista la candidatura. No se prometen nuevos escritores core.
- Migración nueva `qq00r9931t17`, hija de `pp99q8820s16`: locks padre→hijo NOWAIT,
  comprobación de propietarios, snapshot histórico sin truncar y eliminación de
  la FK CASCADE exacta. UUID, contenido, fecha y metadata previos se conservan.
- Downgrade: se niega con cualquier documento presente, sin borrar ni perder
  contexto. Con base vacía puede volver al esquema anterior. Una reversión con
  documentos exige reconciliación; no se arregla destruyendo datos para pasar.

## Identidad y acceso visible

- Backend **be5a1f1**: `CORE_DOCUMENT_OWNER_USER_ID` vincula explícitamente
  el entero local al `CORE_PROFILE_ID` de enrolamiento. Sin vínculo: 503;
  usuario distinto: 404; ambos ANTES de consultar el core. No se infiere el
  dueño de la identidad que solicita la generación.
- Frontend **8836254**: biblioteca de documentos guardados, independiente del
  Kanban, con TODAS las versiones, contexto, idioma y fecha. Descarga PDF/JSON
  por ID y borrado individual confirmado; cancelación/error no retiran la fila.
  No ofrece regenerar desde una candidatura eliminada. Se consulta al abrir o
  refrescar, sin polling nuevo. Traducciones en los seis idiomas existentes.
- El binding se configura durante el preflight con identidad comprobada, no
  adivinando el primer admin. El usuario/modelo/tenant del cliente de candidaturas
  mono-propietario existente no se amplía implícitamente.

Los tests de candidatura SOLO core usan el puerto simulado para casos dueño/
ajeno/ausente/indisponible/borrado durante LLM. Los contratos de almacenamiento
se ejercen con HTTP/auth/PG reales por separado. **Esto no sustituye el canary
integrado en NAS** ni prueba todavía generación→escritor documental core.

Ensayo migración con datos: mismos UUID/contenido/fechas/metadata antes/después,
snapshot completo y supervivencia al DELETE; downgrade con documentos rehúsa y
mantiene versión/datos; base vacía permite down/up. Un propietario incoherente
o lock ocupado aborta antes de dejar DDL parcial. No se reescriben migraciones
publicadas. El arnés PG actualizado crea cuatro tablas sintéticas privadas.

Una primera suite completa, anterior a los dos guards de binding, dio 1906 passed;
la cifra final es la de 1908, no se suman. Core y BFF SwissJob completos no se
repitieron porque no cambió su lógica en E.5. Avisos: caché pytest no escribible,
tests React de inactividad sin `act`, build sin `VITE_API_BASE_URL` y ciclo de
chunks vendor-maps/vendor-react. El build local NO se distribuye como release;
su configuración efectiva debe verificarse en el build de despliegue.
